# Non-Functional Requirements Registry

> Source requirements below are preserved from the supplied Palermo project requirements. The measurable acceptance criteria and verification methods are project-defined SRS refinements; they must not be represented as verbatim client wording.

> Validation profile and interpretation rules are defined in `docs/testing/nfr-validation-profile.txt`.

## Interpretation

- Numeric thresholds in the acceptance-criterion column are project-defined validation targets, not claims that the client supplied those exact numbers.
- The source requirement remains authoritative for traceability; the acceptance criterion makes that source requirement testable for this capstone implementation.
- Where third-party service latency is excluded, Palermo still records and surfaces integration failures/latency through the monitoring criterion.
- The current delivery baseline is the internal delivery simulator; the source wording referring to courier integration is preserved and supported through the delivery-provider abstraction.
- These criteria do not create a production SLA, zero-loss guarantee, tax rule, refund policy, split-shipment capability or other new business scope.
