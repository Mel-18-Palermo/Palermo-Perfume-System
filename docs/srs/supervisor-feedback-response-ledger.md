# Supervisor Feedback Response Ledger

## Purpose

This ledger is the canonical source for Final SRS Section 15: Responses on feedback from project supervisor.

Only real supervisor/lecturer feedback should be entered here.

Do not invent generic feedback, infer feedback from the marking rubric, or convert internal team review comments into supervisor feedback.

## Evidence rule

Each feedback item should preserve enough evidence to show:

- what feedback was actually given;
- when/source context;
- the team's response;
- which SRS artefact changed;
- where the change can be verified.

## Status values

Use:

- `OPEN` — feedback identified but response not yet complete;
- `ADDRESSED` — change completed and evidence exists;
- `ACCEPTED_NO_CHANGE` — feedback considered and a documented reason exists for no SRS change;
- `SUPERSEDED` — later supervisor direction explicitly replaces the item.

## What qualifies as repository evidence

Preferred evidence:

- GitHub issue number;
- pull request number;
- final file path;
- diagram path;
- decision-register entry where the response changed an approved decision.

Do not use "done" or "fixed" without a concrete evidence location.

## Final report rule

Section 15 should be written from this ledger after all actual feedback has been entered and verified.

If no supervisor feedback exists for a particular area, do not manufacture a response.
